umask, специальные биты (SUID, SGID, sticky) и ACL

1. umask — какие права НЕ получит новый файл
Программы создают файлы с правами 666 (rw-rw-rw-), а каталоги — с 777. umask вычитает из них биты:
  umask             — текущее значение, например 0022
  0022: файл 666 - 022 = 644 (rw-r--r--), каталог 777 - 022 = 755
  0027: файл 640, каталог 750 — группа только читает, остальные ничего не видят
  0002: файл 664, каталог 775 — группа может писать
Значения по умолчанию в Ubuntu: у root 0022, у обычных пользователей 0002 (у каждого своя личная
группа, поэтому давать ей запись безопасно). Задаётся это в /etc/login.defs (UMASK, USERGROUPS_ENAB).
  umask 027         — изменить для текущей оболочки (до выхода)
Чтобы изменить навсегда для одного пользователя — строка umask 027 в его ~/.bashrc.
Бит x umask не добавляет никогда: файл с umask 000 получит 666, а не 777.

2. Специальные биты
Перед тремя обычными цифрами прав может стоять четвёртая: chmod 4755, 2770, 1777.
  4 — SUID (u+s) на исполняемом файле: программа выполняется с правами ВЛАДЕЛЬЦА файла.
      Пример: /usr/bin/passwd принадлежит root и имеет SUID — поэтому обычный пользователь может
      записать свой пароль в /etc/shadow. ls -l: -rwsr-xr-x
  2 — SGID (g+s):
      на каталоге — новые файлы и подкаталоги получают группу КАТАЛОГА, а не основную группу автора.
                    Это основа общих каталогов для команды. ls -ld: drwxrws---
      на файле    — программа выполняется с правами группы файла.
  1 — sticky (+t) на каталоге: удалить или переименовать файл может только его владелец
      (или владелец каталога, или root), даже если у всех есть право записи в каталог.
      Так устроен /tmp: drwxrwxrwt
Символьная форма: chmod u+s file, chmod g+s dir, chmod +t dir, убрать — u-s, g-s, -t.
Заглавная буква в ls -l (S или T) значит, что специальный бит стоит, а бита x под ним нет —
обычно это ошибка: chmod 4644 даст -rwSr--r--, и SUID не работает.
Найти все SUID-файлы: find / -perm -4000 -type f 2>/dev/null
Найти каталоги с SGID: find /srv -perm -2000 -type d

3. ACL — права для конкретных пользователей и групп
Обычных прав хватает на одного владельца, одну группу и "всех остальных". ACL (access control list)
добавляет записи для любых пользователей и групп. Нужен пакет acl (команды getfacl и setfacl).
  getfacl file                         — показать ACL
  setfacl -m u:bob:r file              — дать пользователю bob чтение
  setfacl -m g:dev:rw file             — дать группе dev чтение и запись
  setfacl -x u:bob file                — убрать запись для bob
  setfacl -b file                      — убрать все ACL
  setfacl -R -m g:dev:rX dir           — рекурсивно (X — x только каталогам)
Если у файла есть ACL, ls -l показывает + после прав: -rw-r-----+

Чтобы прочитать файл, нужен ещё и x на КАЖДОМ каталоге пути к нему. Если каталог закрыт (например, 2770),
ACL на одном файле не поможет — "Permission denied". Дайте право прохода через каталог:
  setfacl -m u:carol:x /srv/share     — carol сможет открыть файл по имени, но не увидит список файлов (для этого нужен r)
Права на всём пути сразу показывает namei -l /srv/share/report.txt

ACL по умолчанию (default) на каталоге — их наследуют новые файлы и подкаталоги:
  setfacl -d -m g:dev:rwx /srv/share
  getfacl /srv/share                   — строки default:... описывают наследование
Новый файл получит group:dev:rwx, но с пометкой #effective:rw- — файлы создаются без x.
Если у каталога есть ACL по умолчанию, umask для новых файлов в нём не применяется: права берутся из default-записей.

Маска (mask) — верхняя граница для всех записей ACL, кроме владельца и "остальных".
Ловушка: если у файла есть ACL, chmod g-... меняет не права группы, а маску.
  setfacl -m u:bob:r report.txt; chmod g-r report.txt
  getfacl report.txt   →  user:bob:r--  #effective:---   — bob больше не может читать
Проверяйте результат через getfacl: важна колонка #effective.

ACL сохраняются не всеми командами копирования:
  cp file copy        — ACL теряются
  cp -a file copy     — ACL сохраняются
  tar --acls -cf ...  — сохранить ACL в архиве (и --acls при распаковке)
