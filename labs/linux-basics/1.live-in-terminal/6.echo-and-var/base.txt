Использование echo и переменных
Команда echo — это базовая команда в Unix/Linux, используемая для вывода текста на экран. Её можно использовать в комбинации с переменными для отображения значений, хранящихся в переменных, или для записи этих значений в файлы.

Переменные — это именованные контейнеры, которые хранят данные. Переменные используются для хранения значений, которые можно использовать в скриптах или командах. Переменные задаются и используются следующим образом:

Создание и использование переменной:

Создать переменную:
my_variable="Hello, World!"
Пробелов вокруг = быть не должно: my_variable = "x" bash поймёт как запуск команды my_variable с аргументами.

Использовать переменную:
echo "$my_variable"
Берите переменную в двойные кавычки. Без них bash разобьёт значение по пробелам: например, если в logfile лежит "my log.txt",
то echo test > $logfile завершится ошибкой "ambiguous redirect". В одинарных кавычках ('$my_variable') переменная не подставляется.

Этот пример создаёт переменную my_variable со значением "Hello, World!" и затем выводит её значение с помощью команды echo.
Командная подстановка: Используется для выполнения команды и сохранения её вывода в переменной. Это полезно для хранения результатов команд в переменных.

Пример:
current_date=$(date)
echo "Today is $current_date"

Этот пример сохраняет текущую дату в переменной current_date и выводит её.

Арифметика: целочисленные вычисления выполняются в $(( )):
x=2; y=3
echo $((x + y))
Выведет 5. Внутри $(( )) знак $ перед именами переменных можно не писать.

Переменные оболочки и переменные окружения
Обычная переменная видна только в текущей оболочке. Запущенные из неё программы (дочерние процессы)
получают только переменные ОКРУЖЕНИЯ — те, что помечены export:
  X=1; bash -c 'echo "[$X]"'          — выведет [] : дочерний bash X не видит
  export X; bash -c 'echo "[$X]"'     — выведет [1]
  Y=5 bash -c 'echo "[$Y]"'           — переменная только для одной команды, в текущей оболочке Y не появится
  unset X                             — удалить переменную
  env или printenv                    — все переменные окружения; printenv HOME — одна
Добавить каталог в PATH: export PATH="$PATH:$HOME/bin" (новый каталог — в конец, системные команды не перекроются).
Всё это живёт до выхода из оболочки. Чтобы настройка сохранялась, её записывают в файлы профиля.

Какие файлы читает bash
  login-оболочка (вход по ssh, su -, sudo -i):
      /etc/profile  →  /etc/profile.d/*.sh  →  ~/.bash_profile или ~/.profile
      (в Ubuntu ~/.profile в свою очередь читает ~/.bashrc)
  интерактивная не-login оболочка (новая вкладка терминала, команда bash):
      /etc/bash.bashrc  →  ~/.bashrc
  /etc/environment — не скрипт, а список строк ИМЯ=значение без export. Его читает модуль PAM при входе,
      поэтому переменные оттуда видны при любом входе, но $-подстановки в нём не работают.
Куда что класть:
  переменная для одного пользователя         — ~/.profile (или ~/.bashrc для интерактивной работы: алиасы, приглашение)
  переменная для всех пользователей          — отдельный файл /etc/profile.d/имя.sh со строкой export ...
  простое ИМЯ=значение для всех и для служб  — /etc/environment
Ловушка Ubuntu: в начале ~/.bashrc стоит проверка "если оболочка не интерактивная — выйти".
Поэтому export, дописанный в конец ~/.bashrc, не сработает в su - user -c 'команда', в скриптах и в cron.
Применить изменения без перезахода: source ~/.profile (или точка: . ~/.profile).
source выполняет файл в ТЕКУЩЕЙ оболочке; bash файл.sh запускает отдельный процесс, и его переменные пропадут.
Проверить, что увидит пользователь при входе: sudo -iu alice printenv ИМЯ
(sudo -u alice без -i профили не читает и покажет другое окружение).
