Где пригодится каждая команда карточки
======================================

Для каждой из 26 команд card.txt — ситуации из работы администратора и разработчика.
Номера совпадают с задачами из tasks.txt. Пути — как в обычной установке Ubuntu.
Где нужен доступ к чужим файлам (/var/log, /var/lib), добавьте sudo.

── LV1 · LOOKER ─────────────────────────────────────────────────────────

01  ls — осмотреться
    - Зашли на сервер по ssh и не помните, что лежит в домашнем каталоге:
        ls
    - После tar -xf app.tar.gz или git clone узнать, как называется появившийся каталог,
      чтобы в него перейти:
        ls
    - Скрипт должен был выложить отчёт — проверить, что файл и правда появился:
        ls /srv/reports

02  ls /etc ~ /tmp — несколько каталогов за раз
    - Какие сайты nginx есть и какие из них включены:
        ls /etc/nginx/sites-available /etc/nginx/sites-enabled
    - Сравнить два релиза перед переключением:
        ls /opt/app/releases/v1 /opt/app/releases/v2
    - Убедиться, что ночной бэкап разложился во все нужные каталоги:
        ls /backup/db /backup/files /backup/configs

03  ls -1 — одно имя на строку
    - Скопировать список файлов в тикет или письмо: в столбик он читается и копируется
      без лишних пробелов.
        ls -1 /etc/apt/sources.list.d
    - Длинные имена (образы, архивы с датой и версией) в колонках переносятся
      и путаются; по одному на строку видно каждое целиком.
    - Узкая панель tmux или окно 80 символов: колонки ломаются, столбик — нет.

04  ls *.conf — шаблон с *
    - nginx подключает из conf.d только файлы *.conf (include /etc/nginx/conf.d/*.conf),
      поэтому default.conf.bak рядом не работает. Посмотреть, что реально подключится:
        ls /etc/nginx/conf.d/*.conf
    - Перед удалением по шаблону сначала посмотреть, что под него попадёт, и только
      потом удалять тем же шаблоном:
        ls *.tmp
    - Логи приложения за март:
        ls /var/log/app/app-2026-03-*.log

05  ls ?a?? — шаблон с ?
    - ? — ровно один символ. Диски без разделов: sda и sdb подходят, sda1 — нет
      (в облаке диски бывают vda или nvme0n1 — шаблон другой):
        ls /dev/sd?
    - Сжатые ротированные логи с номером из одной цифры, без syslog.10.gz:
        ls /var/log/syslog.?.gz
    - Отчёты report-1 … report-9, но не report-10:
        ls report-?.txt

06  ls [ab]* — шаблон с набором [ ]
    - Только первые два диска:
        ls /dev/sd[ab]
    - Исходники и заголовки C, без объектных .o:
        ls *.[ch]
    - Файлы с заглавной буквы — README, Makefile, Dockerfile.
      Класс [[:upper:]] надёжнее, чем [A-Z]: диапазоны зависят от локали
      и настроек bash.
        ls [[:upper:]]*
    - Логи, у которых после точки одна цифра: syslog.1, auth.log.1:
        ls /var/log/*.[0-9]

── LV2 · DOT-FILE DETECTIVE ─────────────────────────────────────────────

07  ls -a — всё, включая скрытое
    - Найти настройки программ в домашнем каталоге: .bashrc, .ssh и .gitconfig
      без -a не видны.
        ls -a ~
    - rmdir пишет «Directory not empty», а ls ничего не показывает —
      внутри скрытые файлы:
        ls -a old-project
    - Есть ли в репозитории .gitignore, .env, .dockerignore:
        ls -a

08  ls -A — скрытое без . и ..
    - Проверить в скрипте, пуст ли каталог: ls -A печатает пустоту только для пустого
      каталога (ls -a всегда покажет хотя бы . и ..):
        [ -z "$(ls -A /mnt/backup)" ] && echo "диск бэкапов не смонтирован или пуст"
    - Увидеть всё, что попадёт в архив домашнего каталога, без служебных записей:
        ls -A ~
    - Посчитать файлы вместе со скрытыми — см. 23.

09  ls -F — метки типа
    - Вывод вставлен в чат или тикет, цветов нет, а надо отличить каталоги (/)
      от файлов.
    - Распаковали установщик — сразу видно, какой файл исполняемый (*), а какому нужен
      chmod +x:
        ls -F
    - В Ubuntu 22.04+ /bin, /sbin и /lib — ссылки на /usr (@):
        ls -F /

10  ls -p — слэш только у каталогов
    - Отделить каталоги от файлов для grep — без *, @ и |, которые добавил бы -F:
        ls -p | grep /         # только каталоги
        ls -p | grep -v /      # только файлы
    - Скопировать имена файлов: метки -F (* и @) мешали бы вставить имя в команду.

11  ls -d */ — только каталоги
    - Какие проекты лежат в рабочем каталоге — без файлов вперемешку:
        ls -d */
    - Чьи домашние каталоги есть на сервере:
        ls -d /home/*/
    - Все каталоги-наборы конфигов: cron.d, pam.d, sudoers.d, logrotate.d —
      сами каталоги, а не их содержимое:
        ls -d /etc/*.d

── LV3 · LONG-LIST LEGEND ───────────────────────────────────────────────

12  ls -l — права, владелец, размер, дата
    - Сервис пишет «Permission denied» — проверить, может ли www-data читать файл:
        ls -l /var/www/html/index.html
    - Узнать, правили ли конфиг после перезапуска сервиса: колонка даты изменения.
        ls -l /etc/nginx/nginx.conf
    - Какой часовой пояс настроен: /etc/localtime — ссылка на файл зоны.
        ls -l /etc/localtime
    - Перед запуском скрипта убедиться, что у него есть x:
        ls -l deploy.sh

13  ls -lh — размеры для человека
    - Диск заполняется — в каком логе дело: 2.3G сразу видно среди 12K.
        ls -lh /var/log
    - Не оборвалась ли закачка образа — сравнить размер с указанным на сайте:
        ls -lh ~/Downloads/ubuntu-24.04-live-server-amd64.iso
    - Насколько сжался дамп базы:
        ls -lh dump.sql dump.sql.gz

14  ls -li — номера inode
    - Жёсткая ссылка или копия? Одинаковый inode — один и тот же файл под двумя именами.
      Живой пример в Ubuntu: perl и perl5.XX — один файл, счётчик ссылок 2.
        ls -li /usr/bin/perl /usr/bin/perl5.*
    - Удалить файл с непечатными символами в имени, которое не набрать: узнать inode
      и удалить по номеру:
        ls -li
        find . -maxdepth 1 -inum 123456 -delete
    - Снапшоты через жёсткие ссылки (rsync --link-dest): неизменённый файл в двух
      снапшотах должен иметь один inode — значит, место он занимает один раз.

15  ls -R — рекурсивно
    - Что получит новый пользователь в домашнем каталоге (вместе со скрытыми):
        ls -aR /etc/skel
    - Посмотреть целиком структуру небольшого проекта или распакованного архива:
        ls -R myapp
    - Осторожно: на больших деревьях (/, /usr) вывод огромный. Для поиска — find,
      для обзора — tree или find -maxdepth 2.

── LV4 · SORT SORCERER ──────────────────────────────────────────────────

16  ls -lt — свежие сверху
    - Что поменялось в /etc после установки пакета или чужой правки:
        ls -lt /etc | head
    - Какой лог пишется прямо сейчас:
        ls -lt /var/log | head -5
    - Имя самого свежего бэкапа — для скрипта восстановления:
        ls -t /backup/*.tar.gz | head -1

17  ls -ltr — свежие внизу
    - Смотреть каталог логов или загрузок: новые файлы оказываются внизу, рядом с
      приглашением, и не уезжают за верх экрана:
        ls -ltr /var/log
    - Восстановить хронологию инцидента: в каком порядке менялись файлы приложения:
        ls -ltr /var/www/app
    - После сборки посмотреть, какие артефакты появились последними:
        ls -ltr build

18  ls -lS — большие сверху
    - Что занимает место в каталоге, который заполнил диск:
        ls -lS /var/log
    - Что почистить в каталоге core-дампов или кэша в первую очередь:
        ls -lS /var/crash
    - Самые тяжёлые файлы в «Загрузках»:
        ls -lS ~/Downloads

19  ls -lSr — маленькие сверху
    - Бэкап на 0 байт — признак, что дамп упал. Пустые и подозрительно маленькие файлы
      видны в начале списка:
        ls -lSr /backup
    - Лог нулевого размера — служба не пишет в него, хотя должна:
        ls -lSr /var/log/app
    - Найти пустые файлы-маркеры (.lock, .pid), оставшиеся после падения программы:
        ls -lSr /run/app

20  ls -X — по расширению (заглавная X)
    - Разобрать «Загрузки»: все .deb вместе, все .iso вместе, все .pdf вместе:
        ls -X ~/Downloads
    - Остатки обновлений пакетов в /etc: .bak, .dpkg-old и .dpkg-dist идут группами,
      их легко заметить рядом с рабочими .conf:
        ls -X /etc/nginx
    - Каталог проекта по типам: .c, .h и .o отдельными группами:
        ls -X src
    - Не путайте со строчной -x: она выводит имена строками и по расширению
      не сортирует.

21  ls -U — без сортировки
    - Каталог с сотнями тысяч файлов (сессии PHP, очередь, кэш): ls сначала сортирует
      все имена, а -U этот шаг пропускает и заметно быстрее. Посмотреть несколько имён:
        ls -U /var/lib/php/sessions | head
    - Понять, почему find выдаёт файлы в «случайном» порядке: он идёт в порядке
      каталога — том же, что показывает ls -U.

── LV5 · THE LORD OF THE LiSt ───────────────────────────────────────────

22  ls -l link — сама ссылка
    - Какой релиз сейчас развёрнут, если current — ссылка на каталог релиза:
        ls -l /var/www/app/current
    - Какие сайты nginx включены: в sites-enabled лежат ссылки на sites-available:
        ls -l /etc/nginx/sites-enabled
    - Какая версия java или python выбрана через update-alternatives:
        ls -l /etc/alternatives/java
    - Ловушка: ls -l current/ со слэшем покажет уже содержимое каталога, а не ссылку.

23  ls -A | wc -l — посчитать со скрытыми
    - Растёт ли очередь: сколько файлов ждут обработки:
        ls -A /var/spool/app/queue | wc -l
    - Сколько сессий PHP на сервере — грубая оценка активных пользователей:
        ls -A /var/lib/php/sessions | wc -l
    - Проверка для мониторинга: больше 1000 файлов в каталоге загрузок — тревога.
    - Ловушка: ls | wc -l без -A не посчитает скрытые файлы. Имя с переводом строки
      посчитается дважды — для таких случаев есть find.

── POWER COMBOS ─────────────────────────────────────────────────────────

24  ls -lah — всё и сразу
    - SSH не принимает ключ — проверить права. Приватный ключ должен быть 600:
      если его могут читать другие, ssh откажется им пользоваться. Каталог ~/.ssh — 700:
      если в него могут писать группа или все, sshd на сервере не примет authorized_keys.
        ls -lah ~/.ssh
    - Первый осмотр незнакомого каталога: скрытые файлы, права, владельцы, размеры.
    - Перед деплоем проверить .env и другие скрытые конфиги: есть ли они, какого
      размера, кто владелец.

25  ls -ld */ — подробно только каталоги
    - У какого сайта неправильный владелец или права:
        ls -ld /var/www/*/
    - Закрыты ли домашние каталоги от чужих (750 или 755?):
        ls -ld /home/*/
    - Ловушка: ссылка на каталог с */ превращается в current/ — и ls показывает уже сам
      каталог-цель (d в начале строки), а не ссылку.

26  ls -lhS | head -5 — топ по размеру
    - Быстрый ответ на «что съело место»: первая строка — total, за ней четыре самых
      больших файла каталога:
        ls -lhS /var/log | head -5
    - Самые большие программы в /usr/bin (в чистом контейнере Ubuntu 24.04 —
      perl, bash, tar):
        ls -lhS /usr/bin | head -5
    - ls смотрит один каталог, без подкаталогов. Для всего дерева:
        du -ah /var/log | sort -h | tail -5
