# Сертификация `ls`: The Lord of the LiSt

> *One command to list them all.*

Звание для того, кто освоил `ls`: 26 коротких задач, **одна задача — одна команда**.
Задачи повторяют карточку [card.txt](card.txt): каждая команда карточки — одна задача, в том же порядке.
Проверку делает скрипт, а за полный результат он выдаёт сертификат.

⏱ 20–40 минут · сложность: начальная · пререквизиты: тема [`1.ls-and-history`](../base.txt) и
[шаблоны `* ? [ ]`](../group-symbols/hints.txt)

## Ранги

Ранг даётся за уровень, закрытый целиком. Уровни идут по порядку: LV3 не засчитается, пока не закрыты LV1 и LV2.

| Уровень | Ранг | Задачи | Команды карточки |
|---|---|---|---|
| LV1 | Looker | 01–06 | `ls`, `ls /etc ~ /tmp`, `ls -1`, `ls *.conf`, `ls ?a??`, `ls [ab]*` |
| LV2 | Dot-File Detective | 07–11 | `ls -a`, `ls -A`, `ls -F`, `ls -p`, `ls -d */` |
| LV3 | Long-List Legend | 12–15 | `ls -l`, `ls -lh`, `ls -li`, `ls -R` |
| LV4 | Sort Sorcerer | 16–21 | `ls -lt`, `ls -ltr`, `ls -lS`, `ls -lSr`, `ls -X`, `ls -U` |
| LV5 | **The Lord of the LiSt** | 22–26 | ловушки `ls -l link`, `ls -A \| wc -l` и power combos `ls -lah`, `ls -ld */`, `ls -lhS \| head -5` |

## Как сдавать

Root не нужен, подойдёт любая Linux-машина с GNU coreutils. Проверено на Ubuntu 22.04 и 24.04.

```bash
cd '1.ls-and-history(wadd)/ls-certification'   # кавычки обязательны: в имени скобки
./setup.sh          # создаёт арену ~/ls-arena и файл ответов ~/ls-answers.txt
```

1. Откройте [tasks.txt](tasks.txt). Пробуйте команды в арене: `cd ~/ls-arena`.
2. Команду, которая решает задачу, впишите в `~/ls-answers.txt` рядом с её номером: `01 ls`.
3. Запустите `./check.sh` — в любой момент и сколько угодно раз.
4. Справка — только `man ls` и `ls --help`, как на LFCS. [card.txt](card.txt) — шпаргалка с ответами:
   по ней готовятся до попытки и повторяют после, но не открывают во время сдачи.

`./check.sh --card` дополнительно печатает карточку, где решённые задачи отмечены `[x]`.
Когда решены все 26, скрипт печатает сертификат на ваше имя. Чтобы указать другое имя:
`LS_CERT_NAME='Ada Lovelace' ./check.sh`.

Так выглядит частично заполненный файл ответов (вывод снят с Ubuntu 24.04):

```
── LV1 · LOOKER
[ OK ] 01  ls
[ OK ] 02  ls etc logs
[FAIL] 03  ls
       вывод совпал: в конвейере ls и так пишет по имени в строке. В терминале будут колонки — нужен флаг
[FAIL] 04  ls etc/*conf*
       вывод другой, строка 3
         ожидалось: etc/sysctl.conf
         у вас:     etc/resolv.conf.bak
[ -- ] 05  нет ответа
```

А так — итог после 26 из 26, перед карточкой с отметками:

```
╔══════════════════════════════════════════════════════════════════════╗
║                      CERTIFICATE OF ACHIEVEMENT                      ║
║                       THE LORD OF THE  L i S t                       ║
║                          awarded to student                          ║
║         26 of 26 tasks · one task, one command · 2026-10-24          ║
```

## Правила ответа

- Одна строка — одна команда: без `;`, `&&`, `||`, `>`, `<` и `$(...)`.
- Команда начинается с `ls` (можно `\ls` или `command ls`).
  Перед командой можно задать переменную окружения: `LC_ALL=C ls`.
- Конвейер разрешён только в задачах 23 и 26: один `|`, после него `wc`, `head` или `tail`.
- Пути — от арены: `logs`, а не `/home/user/ls-arena/logs` (полный путь тоже примут).

## Как проверяется ответ

`check.sh` запускает вашу команду и эталонную в одной и той же арене и сравнивает их вывод и код возврата.
Поэтому засчитывается любая равносильная запись: `ls -lt logs`, `ls -l -t logs` и `ls logs --sort=time -l`
печатают одно и то же. Владелец, даты и размеры не мешают: у обеих команд они одинаковые.

Скрипт читает вывод через конвейер, а не с терминала. Там `ls` и так печатает одно имя на строку, без
цвета и без кавычек. Поэтому `ls` и `ls -1` выводят одно и то же, и задачи 03 и 21 дополнительно требуют
нужный флаг (`-1` и `-U`). Без него в терминале результат был бы другим.

`check.sh` ничего не меняет: `ls`, `wc`, `head` и `tail` только читают арену. `setup.sh` ничего не удаляет
и не перезаписывает. Если арена или файл ответов уже есть, он их не трогает.

Пути меняются переменными `LS_ARENA` и `LS_ANSWERS` — они действуют и для `setup.sh`, и для `check.sh`.

## Для автора задач

- `tests/selftest.sh` — самопроверка в новом временном каталоге. Она доказывает, что:
  - карточка, задания, шаблон, эталон и ошибки описывают одни и те же задачи (их число берётся из `TOTAL` в `check.sh`);
  - пустой шаблон даёт 0 баллов, эталон — все задачи и сертификат;
  - каждая ошибка из `tests/mistakes.txt` получает FAIL, то есть задача отличает верный ответ от ошибки;
  - варианты из `tests/alternatives.txt` засчитываются;
  - ответы из `tests/rule-breakers.txt` отклоняются;
  - `check.sh` не меняет арену.

  Скрипт ничего не удаляет, поэтому запускайте его в одноразовом контейнере:
  `docker run --rm -v "$PWD:/cert:ro" ubuntu:24.04 /cert/tests/selftest.sh`.
- Новая задача добавляется в шести местах, и номера везде должны совпадать:
  1. `tasks.txt` — условие;
  2. `card.txt` — клетка `[ ]` на том же месте по порядку;
  3. `check.sh` — строка `task` с эталоном, `TOTAL` и границы уровней в `LEVELS`;
  4. `answers-template.txt`;
  5. `solutions/answers.txt`;
  6. `tests/mistakes.txt` — ошибка, которую задача обязана поймать.

  Если данных в арене не хватает, допишите их в `setup.sh`.
- CI: workflow [`linux-basics-lint`](../../../../../.github/workflows/linux-basics-lint.yml) гоняет самопроверку в
  Ubuntu 22.04 и 24.04 от root и от обычного пользователя, а также shellcheck и текстовый линт.
